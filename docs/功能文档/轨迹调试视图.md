# 轨迹调试视图（功能文档）

> 面向使用者与维护者。轨迹调试视图回答一个排障问题：**这一轮到底给模型发了什么、
> 模型回了什么、中间调用了哪些工具**。默认关闭；打开后按用户维度采集，只读展示。
>
> 核心文件：
>
> - 采集与脱敏：`backend/app/runtime/trace.py`
> - 运行接线：`backend/app/runtime/service.py`（`_start_trace` / `consume_run`）
> - 网关采集：`backend/app/api/_forward.py`、`backend/app/runtime/recording_gateway.py`
> - 读取接口：`backend/app/api/conversations.py` 的 `GET /{id}/trace`
> - 前端：`frontend/src/components/TraceDrawer.tsx`、`TraceTimeline.tsx`、
>   `TraceEntry.tsx`、`TraceSettingsSection.tsx`、`frontend/src/lib/trace.ts`

---

## 1. 功能概述

轨迹是对话的旁路数据，不参与消息渲染，也不写回消息表。它记录五类事件：

| 类型 | 记录什么 |
| --- | --- |
| `context_snapshot` | 本轮组装完成后的上下文：system prompt、prompt、历史元数据、模型、工作目录、内核会话 id、技能与 MCP 列表 |
| `request` | 发给模型的请求：HTTP 请求体、CLI 启动参数 / stdin、网关转发的真实报文 |
| `response` | 模型响应：HTTP 响应体、流式拼装结果、CLI 终态输出、网关响应 |
| `tool_call` | 工具名、调用 id、入参 |
| `tool_result` | 工具输出、是否报错 |

三类传输在 `payload.transport` 里区分：

- `http`：API 型内核（两个 Harness）自己发 HTTP；
- `cli`：CLI 内核的进程入参与终态输出（平台看不到子进程内部 HTTP 报文）；
- `gateway`：记录网关转发的真实请求 / 响应（CLI 内核的模型报文在这里可见）。

---

## 2. 开关与入口

### 2.1 开关

- 权威真值在 `users.trace_debug`（用户级，默认 `false`）；
- 设置页「对话」分组里的 `TraceSettingsSection` 只读这个字段，修改走
  `PATCH /api/users/me`；
- 关闭时运行层不创建 `TraceRecorder`：零采集、零写库、零开销。

### 2.2 入口

对话页工具栏「新建对话」旁出现调试按钮，显隐只认 `user.trace_debug`。点开是右侧抽屉，
不改变原对话布局，也不触发重放或新运行。

---

## 3. 采集范围

### 3.1 有注入缝的内核

记录网关的判定只看适配器是否声明 `Capabilities.recording_gateway`：

| 内核 | 轨迹来源 |
| --- | --- |
| Claude Code、Codex、Hermes、CodeBuddy | 网关转发（`transport="gateway"`） |
| OpenAI Harness、DeepSeek Harness | 内核自己发 HTTP（`transport="http"`） |
| 豆包、Antigravity、Custom CLI | 没有可写入的 base_url，轨迹如实标「不可见」 |

`capture_trace` 只给 `Runtime.CLI` 的网关目标打开；API 内核自己已经写轨迹，网关层跳过，
避免同一请求记两份。

### 3.2 网关时序

```
CLI 子进程
   │ base_url 指向本机代理
   ▼
/api/internal/usage-gateway/<token>/...
   ├─ 请求体脱敏 → 写 request（transport=gateway）
   ▼
上游真实网关
   ├─ 响应流 tee → 解析 usage 写账本（原有逻辑）
   └─ 终态响应脱敏 → 写 response（transport=gateway）
```

`ProxyTarget` 带 `run_id` / `conversation_id`；转发层用 `registry.get(run_id)` 反查
`ActiveRun.trace`。外部模型 API 的 target 是 `ext:...`，反查不到 run，天然不采。

### 3.3 不采集的内容

- 关闭 `trace_debug` 的用户；
- 外部 API（`/api/model-gateway`）请求；
- 没有注入缝的内核的真实模型报文（只能看到进程入参与终态，不伪造）。

## 4. 数据结构

### 4.1 数据表

`trace_events`：

| 列 | 说明 |
| --- | --- |
| `id` | 主键 |
| `conversation_id` | 平台对话 id，外键 `ON DELETE CASCADE` |
| `owner_id` | 归属用户，便于后续配额 / 保留期 |
| `run_id` | 本轮运行 id，可关联 `turn.started` |
| `turn_index` | 该对话第几轮用户消息（0 起） |
| `seq` | 会话内严格递增，时间线与分页的稳定键 |
| `type` | 五类事件 |
| `payload` | JSON，按类型约定 |
| `duration_ms` | 请求 / 工具耗时；快照为 null |
| `error` | 采集或请求错误摘要 |
| `truncated` | 是否因体积上限被裁剪 |
| `bytes` | 截断前序列化字节数 |
| `created_at` | 采集时刻 |

索引：`(conversation_id, created_at)` 用于时间线读取，`(conversation_id, run_id)`
用于按轮查看。

### 4.2 字段语义

- `session_id` 在响应里指**平台对话 id**（`Conversation.id`），不是内核 session；
  内核会话 id 在 `payload.kernel_session_id`。
- `turn_index` 由 `prepare_run` 统计已有 user 消息得到；`regenerate_last` 取被重跑那条
  的序号。该值只写轨迹，不改 `Message` 表。
- `payload.user_message_id` / `assistant_message_id` 用于从轨迹跳回原消息。
- `tool_call.call_id` 与 `tool_result.call_id` 配对。

## 5. 读取接口

```
GET /api/conversations/{id}/trace?after_seq=0&limit=100
```

- 只读分页，返回 `{items, next_after_seq}`；`next_after_seq` 为空表示没有下一页；
- 排序键是 `seq`，不依赖 `ActiveRun` 内存缓冲，刷新 / 重启后可回看；
- 读取前走 `_owned_conversation` 严格归属校验，管理员不豁免；
- `limit` 最大 500。

## 6. 体积与裁剪

| 限制 | 值 | 行为 |
| --- | --- | --- |
| 单事件 payload | 2 MiB | 超限先做结构感知裁剪，仍超限才退回合法 JSON 的头 / 尾摘要 |
| 单对话事件数 | 500 条 | 按 `created_at` 从旧到新删除 |
| 单对话总体积 | 100 MiB | 按 `bytes` 累加，超限从旧到新裁剪 |
| 单条消息字段 | 256 KiB | 逐字段截断，保留 JSON 结构 |
| 历史正文 | 单条 8 KiB / 总量 32 KiB | 快照里只留元数据 + 截断文本 |

结构感知裁剪优先保留 `messages` 数组的完整性：逐条保留结构，只裁单条超长字段，
从最早的非 system 消息开始丢弃，并写 `truncated=true` / `truncated_messages` /
`original_messages`。排障时「少了几轮」比「整段 JSON 坏掉」更有用。

二进制（图片、base64、附件）一律替换为：

```json
{"__omitted__": "binary", "mime": "image/png", "bytes": 123456}
```

## 7. 安全与脱敏

入库前统一走 `trace.sanitize()`：

1. **凭据值擦除**：复用 `credentials.scrub()`，把用户配置的密钥从文本里擦掉；
2. **敏感键掩码**：`Authorization`、`Cookie`、`api_key`、`token`、`secret` 等键
   统一替换为 `***`，被掩码的路径写进 `redacted_fields`；
3. **内联二进制替换**：data URL / 大段 base64 只留引用与大小；
4. **网关错误体擦除**：passthrough 模式下从客户端请求头收集凭据值，一并擦除，
   防止上游错误体回显 OAuth 令牌。

隐私边界：

- 正文只进 `trace_events`，不进消息表、不进日志；
- 关闭开关后不采集；
- 轨迹随对话删除（外键级联）；
- 不做跨对话全局清理，也不引入定时任务。

## 8. 前端交互

- 右侧抽屉：时间线按 `seq` 排列，可按类型过滤；
- 每条显示类型、时间、耗时、截断标记与错误；
- 请求 / 响应支持查看脱敏后的 JSON，工具调用与结果成对展示；
- 单条可复制原始 JSON；
- **导出**：先把剩余分页拉完，再在前端拼 JSON Blob 下载；默认开启「脱敏导出」，
  隐藏请求头与上下文正文，也可切到原样；
- 只读：不提供编辑、重放、删除入口，所有请求都是 GET；
- 分页懒加载，不预加载整段轨迹；
- 移动端不重复实现调试视图。

## 10. 测试与排错

### 10.1 自动化测试

- `backend/tests/test_trace.py`：脱敏、体积裁剪、结构裁剪、分页、归属。
- `backend/tests/test_gateway_binding.py`：能力判定、网关轨迹、passthrough 擦除。
- `backend/tests/test_recording_gateway.py`：转发与账本，不重复记。
- 全量：`bash scripts/test.sh`；前端 `npm --prefix frontend run build`。

### 10.2 常见问题

| 现象 | 先看什么 |
| --- | --- |
| 抽屉按钮不出现 | `users.trace_debug` 是否为 true？是否在桌面端对话页？ |
| 只有进程入参，没有模型报文 | 该内核是否声明 `recording_gateway`？是否绑了自定义网关或官方 API Key？ |
| 轨迹里出现 `***` | 正常：敏感键被掩码；看 `redacted_fields` 确认范围 |
| 响应被截断 | 看 `truncated`、`bytes`、`truncated_messages`；属于体积上限行为 |
| 关闭开关后仍有旧轨迹 | 旧数据不会删除，只是不再新增；删对话可级联清理 |

## 11. 已知边界

- 没有 MITM 正向代理：豆包、Antigravity、Custom CLI 的真实模型报文不可见；
- CLI 内核平台只能看到子进程 stdout / stderr，网关是唯一能看到真实报文的点；
- 官方 OAuth passthrough 是实验性能力，只在强制开启且内核为 CLI 时生效；
- 轨迹数据会明显增加数据库体积，默认关闭；单对话上限 100 MiB；
- 导出完全在前端完成，默认脱敏；把文件带出平台后的安全由使用者自己负责。
