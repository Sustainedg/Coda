# 内核任务卡桥接 · 三态方案

> 状态：**已实施**（2026-11-27）
> 上游：[`task-progress-card-design.md`](../task-progress-card-design.md) §6.9
> 目标读者：后续给新内核接任务卡的适配器作者、QA

---

## 0. 结论速览

| 决策点 | 结论 |
| --- | --- |
| 统一方式 | **适配器桥接**：内核自带任务工具归一成平台卡片块，平台 `task_cards` 仍是唯一展示源 |
| 三态 | `pending` / `in_progress` / `completed`；`completed` 终态，`pending ↔ in_progress` 可切换 |
| 旧协议 | `done:true` = `completed`；`done:false` = 不改状态；旧卡片行按 `done` 推导 `status` |
| 通用钩子 | `AgentRun.task_card_block` → `ActiveRun.task_card_block` → `consume_run` 兜底 |
| 优先级 | MCP > 围栏 > 内核快照（`source="kernel"`） |
| 不做 | 双向同步、依赖 / 父子 / 优先级、直接读内核会话文件、前端识别内核工具名 |

---

## 1. 为什么是桥接，而不是直接共用内核任务列表

1. **生命周期不同**：内核任务列表属于内核 session；平台卡片属于 conversation。换内核、
   重置记忆、@ 召唤、协作域运行时，两者不完全重合。
2. **数据形态不同**：内核有三态、依赖、父子、删除；平台 P1 只有展示需要的三态。
3. **权威源冲突**：双向同步会引入覆盖顺序 / 回环 / 删除恢复。平台必须保留唯一展示源。
4. **分层铁律**：框架和前端不能认识 `TaskCreate` / `TaskList` 这些内核专有工具；
   映射只能写在**适配器**里。
5. **可移植性**：不是所有内核都有任务工具；平台协议（围栏 / `update_task_card`）仍是
   跨内核的统一入口，内核快照只是兜底。

## 2. 架构

```
CodeBuddy parse_line()
  TaskCreate / TaskUpdate / TaskList
        │ 归一
        ▼
AgentRun.task_card_block = {action, title, items:[{id,text,status,done}]}
        │ runner 收尾复制
        ▼
ActiveRun.task_card_block
        │ consume_run finally
        ▼  仅当本轮没有 MCP 成功写卡、也没有合法围栏块
apply_block(source="kernel")  ← 复用合并 / 乐观锁 / 幂等
        ▼
task_cards（唯一展示源） → 详情接口 → TaskProgressCard
```

- **不新增事件类型**：`task_card_block` 是适配器→运行层的字段，不进 SSE / 前端。
- **不新增数据库列**：`items` 是 JSON，状态直接写进元素。
- **优先级**：本轮有成功的 MCP 调用 → 忽略围栏与内核快照；否则合法围栏块优先；
  围栏没有 / 写坏时才用内核快照。
- **幂等**：`source="kernel"` 与围栏一样按 `last_run_id` 一轮只应用一次。

## 3. 三态语义

| 操作 | 规则 |
| --- | --- |
| `create` 新项 | 取 `status`；没有则按 `done`（true=completed / false=pending） |
| `create` 重规划 | 旧项 completed 保持；旧项非终态按新块状态走；新块没列的 id 删除 |
| `update` | `completed` 终态不可回退；`pending ↔ in_progress` 允许；未知 id 忽略 |
| 旧 `done:true` | 等价 `completed`，写 `done_at` |
| 旧 `done:false` | no-op（保持旧行为，不能把已完成项改回去） |
| 存储字段 | `{id,text,status,done,done_at,updated_at}`；`done = status=="completed"` |
| 读取旧行 | 没有 `status` 时按 `done` 推导，不改库 |

前端 `TaskProgressCard`：已完成 ✓、进行中 ◐、待办 ○；标题栏显示
`进度 1/4 · 进行中 1`；展开后每项右侧显示状态文字。两端样式表共享段保持逐字一致。

## 4. CodeBuddy 映射（P1）

在 `backend/app/agents/builtin/codebuddy_cli.py`：

| 内核事件 | 归一动作 |
| --- | --- |
| `TaskCreate(subject)` + 结果 `Task #N created successfully: ...` | 新增 `tN`，文本=subject，状态 pending |
| `TaskCreate` 失败（`is_error`） | 忽略，不补项（内核里本来就没有这个任务） |
| `TaskCreate` 结果认不出 `Task #N` | 忽略该项（编造 id 会和后续 `TaskList` 撞号） |
| `TaskUpdate(taskId, status)` | 改 `tN` 状态；`status=deleted` 移除 |
| `TaskUpdate` 指向本轮没见过的 id | 忽略，等 `TaskList` 快照补（不塞「任务 #N」占位文本） |
| `TaskList` 结果 `#N [status] 文本` | 整卡快照替换，未出现的项视为删除 |
| 快照不足 2 项 | 不产出块（平台建卡要求 2~20 项） |

适配器状态放在 `run.state["task_card_bridge"]`，仅本轮有效。

## 5. 已知边界 / 后续

- **依赖、父子、优先级**：平台 `items` 还没有这些字段；要做完整对齐需给 item 加
  `depends_on` 等字段，并同步前端 / 移动端 / IM 文案，另开方案。
- **快照不完整**：如果模型整轮没调 `TaskList`，只更新上一轮创建的任务，适配器只看到
  本轮变化；这是有损兜底，不是权威同步。
- **标题**：内核任务没有计划标题，取第一个任务文本作为卡片标题。
- **新内核接入**：在自己的适配器里实现同样的归一，设置 `AgentRun.task_card_block` 即可；
  不需要改 `runtime/service.py` 的优先级逻辑。
- **前端不认内核工具名**：前端只看 `task_card.items[].status`，不解析 TaskCreate/TaskList。
